# stock_picker · 放量选股工具

基于**本地通达信数据**的轻量选股工具：筛出「成交量 ≥ N 倍 M 日均量」的股票，
自动标注**二级行业**与**概念板块**（可选行业 / 概念筛选），列表直接看 K 线，
可为每只股票计划**买入价**与**卖出价（放量日收盘价 × 1.045）**，并一键加入**追踪**列表。

另有三个并列页签：

- **连板梯队**：指定交易日的涨停个股按连板高度分层（含封板形态、晋级率、行业 / 概念分布）
- **板块交集**：求「二级行业 ∩ 概念」的交集个股（多选即筛选，交集为空时给调整建议）
- **计划 / 追踪**：买卖计划与持续追踪（SQLite 落盘，自动备份）

- 后端：FastAPI + pandas/numpy，读取本机 `vipdoc` 的 `.day` 日线文件，无需联网
- 前端：原生 JS 单页 + ECharts（本地文件，无 CDN、无构建步骤）
- 存储：SQLite（计划 / 追踪）；行情缓存为 Parquet

## 1. 快速开始

```bash
# 依赖（本机已具备）
pip install -r stock_picker/requirements.txt

# 启动（默认读取 D:\new_tdx，监听 127.0.0.1:8778）
python -m stock_picker.app --port 8778

# 或
python stock_picker/run.py --tdx-dir D:\new_tdx --port 8778
```

打开 <http://127.0.0.1:8778> 即可用：**服务启动时已在后台把本地数据全部载入**
（首次运行、或本地通达信行情比缓存新时会自动重建缓存，全市场约 8 秒，页面顶部显示进度），
页面打开后还会**自动跑一次选股**，不用手点。详见 [2.9 启动即预加载](#29-启动即预加载)。

命令行参数：

| 参数 | 说明 |
|---|---|
| `--host` / `--port` | 监听地址与端口（默认 `127.0.0.1:8778`，写回 `config.json`） |
| `--tdx-dir` | 通达信安装目录（含 `vipdoc/`）或 `vipdoc` 目录本身 |
| `--reader` | `fast`（默认）/ `pytdx` / `auto`，见第 4 节 |
| `--browser` / `--no-browser` | 启动后自动打开浏览器 / 不打开（打包版默认自动打开） |
| `--reload` | 开发用热重载（**打包版不支持，会自动忽略**） |

> 想直接要一个双击就能跑的 exe？见 **[第 9 节：打包成 exe](#9-打包成-exe-windows)**。

## 2. 功能

### 2.1 选股

| 参数 | 默认 | 说明 |
|---|---|---|
| 均量窗口 | 20 | 均量基准窗口 M |
| 放量倍数 | 2.0 | 当日量 ÷ 前 M 日均量 ≥ 该值 |
| 回看交易日 | 1 | 在最近 N 个交易日内寻找信号；也可指定单日 |
| 指定日期 | 空 | 日期控件，只认交易日：**留空 = 最新交易日**（此时「回看交易日」生效）；选中非交易日会自动吸附到不晚于该日的最近交易日。**可选范围 = 本地 `.day` 的全历史**（1991-01-02 ~ 最新，共 8786 个交易日），右侧「最新」按钮一键清空 |
| 最小成交额 | 0 | 过滤流动性（亿元） |
| 最大流通市值 | 150 | **流通市值 < N 亿元**；`0` = 不限。流通市值 = 流通股本 × 当日收盘价，股本取自本地 `gbbq`，与行情同源、无需联网 |
| 交易所 | 沪深京 | 勾选参与扫描的交易所 |
| 板块 | 仅主板 | 勾选参与扫描的板块；**默认只保留主板** |
| 二级行业 | 全部 | 按**通达信研究行业**二级筛选；可由「行业分布」一键点选 |
| 概念 | 全部 | 按**通达信概念板块**筛选，见 [2.3](#23-概念分类)。输入框支持多个概念（中英文逗号分隔），配合右侧「任一 / 全部」切换并集与交集。可由「概念分布」一键点选 |
| 剔除 ST/退市 | 是 | 按通达信名称表匹配 `ST` / `退` |
| 卖出溢价 | 4.5% | 卖出价 = 放量日收盘价 × (1 + 溢价) |
| 结果排序 | 量比降序 | **点表头排序**，再点同列反向；14 列全部可排。详见 [2.5](#25-结果排序) |
| 最多返回 | 300 | 结果上限，超出时页面会提示「共命中 N 只」 |
| 数据加载 | 启动即预加载 | 服务启动就在后台载入本地全部数据，页面打开**自动跑一次选股**，不用手点。详见 [2.9](#29-启动即预加载) |

**板块划分**（由代码前缀唯一决定，`tdx_reader.board_of`）：

| 板块 | 代码段 | 默认 |
|---|---|---|
| 主板 | 沪 `600/601/603/605`、深 `000/001/002/003` | 纳入 |
| 创业板 | 深 `300/301` | **排除** |
| 科创板 | 沪 `688/689` | **排除** |
| 北交所 | `43/83/87/88/92` | **排除** |

**均量口径**：`ma_volume` 取**前 M 日**（不含当日）成交量均值，
只用当日及之前的数据，不引入未来函数。

**结果去重**：同一只股票在窗口内多次放量时，只保留**最近一次**信号。

### 2.2 二级行业分类

结果表内置「二级行业」列，并有一张「二级行业分布」卡片：

- 分布基数是**除二级行业/概念筛选本身以外的全部条件命中集**（响应里的 `summary_base`）：
  既不是截取后的前 N 只，**也不随行业筛选收缩**。所以点选某个行业后，其余行业标签依然在，
  可以连续切换，也能看出该行业在整体中的占比；
- 点击任意行业标签即按该行业过滤，再点一次取消；也可用筛选区的下拉（按一级行业分组）；
  已选中的行业若排在 40 名开外，会被提到最前，避免「筛了却看不见自己选的是哪个」；
- 计划页、追踪页、K 线抽屉同样显示所属行业。

分类口径为通达信的**研究行业**（`X` 码），三级结构：

| 级别 | 示例 | 数量 |
|---|---|---|
| 一级 | 化工 / 银行 / 房地产 | 30 |
| 二级 | 化学制品 / 全国性银行 / 房地产开发 | 128 |
| 三级 | 聚氨酯 / 股份制银行 / 住宅开发 | 316 |

数据来自本地文件，**不联网**：

- `T0002/hq_cache/tdxhy.cfg` —— 每只标的的行业归属。行格式
  `市场|代码|T码|||X码`（`市场`：0 深 / 1 沪 / 2 京）
- `incon.dat` 的 `#TDXRSHY` 段 —— `码|名称` 名称表

> `incon.dat` 里另有两套分类：`#TDXNHY`（通达信行业，`T` 码）与 `#SWHY`（申万行业，纯数字码）。
> **只有 `T` 码和 `X` 码能通过 `tdxhy.cfg` 映射到具体股票**，申万码在本地没有股票归属文件，
> 因此本工具采用 `X` 码。本地 A 股覆盖率 **99.3%**（5564/5602），命中结果覆盖率 **100%**。

### 2.3 概念分类

结果表内置「概念」列（每行显示前 2 个 + `+N`，鼠标悬停看全部），并有一张「概念分布」卡片：

- 分布基数同样是 `summary_base`（不受行业/概念筛选影响），给出各概念的命中只数、平均每股概念数；
  点选某个概念后其余概念标签依然在，可连续切换；已启用但排在 40 名开外的概念会被提到最前；
- 点击任意概念标签即按该概念筛选（单一概念），再点一次取消；筛选区也可手工输入多个概念
  （中英文逗号分隔，输入框有自动补全），并用「任一 / 全部」决定**并集**还是**交集**
  （例如 `新能源车，固态电池` + 全部 = 同时属于两个概念的标的）；
- 计划页、追踪页、K 线抽屉同样显示概念：抽屉顶部把该股的概念**全量铺开**成标签。

概念口径为通达信的**概念板块**（`GN_` 段），本地实测 **269 个概念**，平均每股 8.55 个，
对 5602 只 A 股覆盖 **97.0%**（5435 只）。

数据来自本地文件，**不联网**：

| 文件 | 作用 |
|---|---|
| `T0002/hq_cache/infoharbor_block.dat` | 板块与成分股。`#<类别>_<板块名>,<声明成员数>,<指数代码>,...` 开头，成分行为 `<市场>#<代码>`（0 深 / 1 沪 / 2 京） |
| `T0002/hq_cache/tdxzs.cfg` | 板块指数表 `板块名\|指数代码\|类型码\|?\|0\|显示名`，**类型码 4 = 概念**（2 行业 / 3 地区 / 5 风格） |

两个文件是**独立来源**，可以互相印证：

| 校验项 | 结果 |
|---|---|
| `GN_` 板块数 vs `tdxzs.cfg` 类型码 4 条数 | 269 = 269 |
| 按**板块指数代码**求交集（名字口径不同时的硬校验） | **269 / 269，双向零残差** |
| 板块头声明的成员数 vs 实际解析出的成分数 | 269 个板块**全部一致，0 条差异** |
| 成分行的市场码 vs 按代码前缀推断的市场 | **冲突 0 条** |
| 抽样常识核对 | `600519` 白酒概念、`002594` 新能源车/锂电池、`601127` 华为汽车、`300750` 固态电池 —— 全部命中预期 |

两点说明：

- **命名口径**：`infoharbor_block.dat` 用简称（「锂电池」「智能机器」），
  `tdxzs.cfg` 用全称（「锂电池概念」「机器人概念」），36 个概念存在这种差异。
  本工具以**板块文件的简称为准**（与行情软件板块列表一致），交叉验证走指数代码。
- **不做主观筛选**：通达信自身把「含H股」「次新股」「ST板块」这类**属性标记**也归在概念里，
  本工具原样保留，避免与行情软件口径不一致。若不想看到，直接在概念输入框里排除即可
  （例如筛「机器人」，不要用 `智能机器` 之外的模糊匹配）。

### 2.4 K 线

点击列表**任意一行**打开右侧抽屉：

- 蜡烛图 + MA5 / MA10 / MA20 / MA60
- 下方量能柱（涨红跌绿）+ M 日均量线
- 量比 ≥ 2 的日子自动打上「放量」标记
- 图上以虚线标出当前计划的**买入价**（蓝）与**卖出价**（红），右上角给出对应价位文字；
  y 轴范围会把这两个价位一并纳入，避免虚线被挤到图外
- 抽屉顶部可直接改买入价/卖出价，改动即时反映在图上，并可保存为计划或加入追踪
- 抽屉宽 `min(1440px, 95vw)`，K 线图占满抽屉内宽；窗口缩放时图表自动 `resize()`
  （`#klineChart` 必须是 `.drawer-body` 的子元素，否则会被 flex 压扁、图高与上方控件都不正常）

> 列表里不设操作按钮：**点行即开抽屉**，抽屉里已包含
> 「保存计划 / 加入计划 / 加入追踪 / 按收盘价重置」全部操作。
> 这样 14 列核心数据（含买入价、卖出价、概念）在 1258px 视口下**一屏可见、无需横向滚动**。

### 2.5 结果排序

14 个表头**全部可点**，点一下即按该列排序，**再点同一列反向**（降序 ↔ 升序）：

- 数字列（收盘价、**涨跌幅**、量比、流通市值、买卖价、成交量、均量、成交额、**概念数**）首次点击为**降序**
- 文本列（代码、名称、二级行业、信号日）首次点击为**升序**，中文按拼音（`localeCompare('zh-Hans-CN')`）
- 默认排序 = **量比降序**，与后端返回顺序一致（不做二次重排）；切换过排序后卡片右上出现
  「恢复默认」按钮可一键回到量比降序
- 缺值（如无涨跌幅）**恒沉底**，不随方向翻转；同值保持后端原序（稳定排序）
- 行内改过买入/卖出价后再排序，**数值跟着股票走**（渲染只改行顺序，不改行下标）
- 导出 CSV 按**屏幕当前排序**输出，与所见一致

### 2.6 计划与追踪

- **计划**：`代码 / 信号日 / 放量日收盘价 / 量比 / 买入价 / 卖出价 / 数量 / 状态 / 备注`，
  状态可选 待买入 / 已买入 / 已卖出 / 已过期 / 放弃，可一键「转追踪」
- **追踪**：在计划基础上补充**实际买入日期与买入价**，并自动计算
  - 最新价、信号日以来的区间最低/最高
  - 是否已触及买入价（区间最低 ≤ 买入价）
  - 是否已达卖出价（区间最高 ≥ 卖出价）
  - 相对买入价的收益率与金额

同一 `(代码, 信号日)` 组合在计划表和追踪表中都是**唯一**的，重复提交为覆盖更新。

### 2.7 数据持久化（计划 / 追踪不会丢）

计划与追踪全部写在 **SQLite**：`data/stock_picker.db`，三层保障：

| 保障 | 做法 | 效果 |
|---|---|---|
| 落盘 | `PRAGMA journal_mode=WAL` + `synchronous=FULL` + `busy_timeout=30000` | 提交即落盘；进程被强杀、机器掉电都不丢已确认的写入 |
| 自动备份 | 启动时、以及每次写入后（距上次 > 6 小时）用 SQLite 官方 `backup()` 生成一致性快照 | 滚动保留最近 40 份，存于 `data/backups/` |
| 可导出 | `GET /api/storage/export` 导出 JSON；`POST /api/storage/backup` 手动快照 | 随时可留档或迁移 |

**恢复方法**：把想要的备份文件（`data/backups/YYYYMMDD-HHMMSS-*.db`）覆盖回
`data/stock_picker.db` 即可（覆盖前请先停掉服务）。备份是**在线快照**，
由 SQLite 保证一致性，不依赖直接拷贝 `.db`/`-wal` 文件，所以不存在半个事务的问题。

页面右上角「备份数据」按钮即 `POST /api/storage/backup`，
侧栏底部会显示当前库文件名与已有备份份数。

### 2.8 界面风格

采用 **macOS Vibrancy** 风格（参考 stylekit 的 macOS Vibrancy 规范）：

- **三档深灰构层次**：`#1c1c1e`（底层/侧栏）→ `#2c2c2e`（内容面板）→ `#3a3a3c`（表头/控件/浮层）
- **1px 半透明描边**：只用 `rgba(255,255,255,.08)` 与 `.12` 两级，不靠阴影做分隔
- **系统级毛玻璃**：侧栏 `rgba(28,28,30,.72)` + `backdrop-filter: blur(28px) saturate(180%)`，
  抽屉同理；被遮罩的页面会真实地透出来
- **三种字体各司其职**：标题 Georgia 衬线、正文系统无衬线、数字/代码 SF Mono
- **克制的动效**：`200ms` 且只过渡颜色；无渐变、无光晕、无 pulse/bounce
- **涨跌沿用中国习惯**：涨红 `#ff453a`、跌绿 `#30d158`
  （取 macOS 深色系统色，保证暗底可读）

> **原生下拉的 `<option>` 必须显式配色**（踩过的坑，2026-10-07）：`:root` 上的
> `color-scheme: dark` 在 macOS 上足够让系统弹层变暗，但 **Windows 上 Chrome/Edge 常把弹层
> 底仍涂成系统默认的白色**，而 `<option>` 文字继承了作者的 `color: var(--text)`（接近纯白）
> → **白底白字，不动鼠标根本看不见，只有 hover 时才显出来**。所以 `style.css` 里有一条全局规则：
>
> ```css
> select option { background-color: var(--surface); color: var(--text); }
> select option:disabled { color: var(--muted); }
> ```
>
> 它只影响弹层、不影响 `<select>` 本体（本体配色由 `.filters select` 负责）。
> 新增任何 `<select>` 都不用再单独处理 —— 这条规则覆盖全站（实测 `#fIndustry` 的 129 个
> option 计算样式均为深底 `rgb(58,58,60)` + 浅字 `rgb(245,245,247)`）。

### 2.9 启动即预加载

「打开就能用」——不用记得先点「刷新数据」再点「开始选股」。

**服务端**：进程一起来就在**后台线程**里把本地已存在的数据全部载入，
端口先就绪、页面先打开，重活在这条线程里干（不会卡住启动）：

| 顺序 | 内容 | 数据源 | 本次实测 |
|---|---|---|---|
| 1 | 名称表 | `T0002/hq_cache/*.tnf` | 52194 条 |
| 2 | 二级行业 | `tdxhy.cfg` + `incon.dat` | 5583 只 / 128 个二级 |
| 3 | 概念板块 | `infoharbor_block.dat` + `tdxzs.cfg` | 269 个概念 / 5442 只 |
| 4 | 流通股本 | `T0002/hq_cache/gbbq` | 5923 只 |
| 5 | **行情缓存** | 全市场 `.day`（缺失、过期或口径变更才重建） | 5605 只 / 17,012,754 行 / 18.8s（全历史） |
| 6 | 内存行情 + 交易日索引 | `bars.parquet` | 常驻约 578.9 MB / 8786 个交易日 |

**「过期」怎么判断**：拿 `bars.parquet` 的 mtime 与本地 `lday/` 目录下最新一个 `.day`
的 mtime 比（`os.scandir`，9741 个文件约 30ms，**不 fopen 全部文件**），
再按 `meta["bars_per_code"]` 与配置里的 `cache_bars` 比对口径
（只比 mtime 发现不了「改了 `cache_bars` 但源文件没变」）。
本地更新（通达信盘后下载了数据）或口径变了 → 自动重建；
已是最新 → **不重建**，整轮预加载 0.3~0.6s 返回。

**前端**：页面打开时先等这次预加载结束（重建期间显示进度条与「本地行情比缓存新，正在重建缓存…」），
然后加载状态/交易日/行业/概念/计数，**自动执行一次选股**，
并把「计划 / 追踪」也预取好——切页即见，不用等。

配置在 `config.json` 的 `bootstrap` 段：

| 键 | 默认 | 说明 |
|---|---|---|
| `preload` | `true` | 启动时在后台预加载；`false` = 回到「手动点刷新」的老行为 |
| `refresh_if_stale` | `true` | 本地行情比缓存新时自动重建缓存 |
| `auto_screen` | `true` | 页面打开后自动跑一次选股 |

进度与结果都能查：`GET /api/bootstrap`（含 `running` / `ready` / 各步 `steps` / 缓存新旧），
`POST /api/preload` 手动重跑一次（等价启动那一次）。
同一时刻只允许一个重建在跑（内部加锁），手点「刷新数据」不会与启动预加载打架。

### 2.10 连板梯队

侧栏「连板梯队」页，参照兄弟应用 `stock_blocks/stock_watch/views/streaks.py` 实现：
把指定交易日的**涨停个股按连板高度分层**，一眼看出当前市场的高度与主线。

- **连板数** = 从所选交易日**往回连续涨停**的天数（首板 = 1）
- **涨停判定**（`limits.py`，与交易所口径一致）：
  - 涨停价 = `round(前收盘 × (1 + 涨跌幅))`，**按「分」整数**算：`(prev_c × f + 50) ÷ 100`，
    用浮点会在 0.01 元边界上抖动
  - 涨跌幅：主板 10% / 创业板·科创板（`300/301/688/689`）20% / 北交所 30%
  - **上市首日剔除**（首日无涨跌幅限制，涨 44% 会被误判）
  - 基准价 = **前一根 K 线的收盘**。`.day` 第 8 个字段名义上是「上日收盘」，
    但实测**自 2015-12-16 起全部失效**（多为占位值 `65536` 或 `0`，北交所从来没有），
    所以不落缓存列（省 68MB），一律用前一根收盘
- **封板形态**：一字板（最低价 = 涨停价）/ T字板（开盘即涨停但盘中打开）/ 换手板
- **指标概览**：涨停家数 / 首板 / 2 连板 / 3 连板及以上 / 最高连板（含名称）/ 一字板数 /
  跌停数 / 触板未封数 / 前一日涨停数 / **晋级率**（今日 2 板及以上 ÷ 前一日涨停）
- **连板高度分布图** + **梯队视图**：每一层横排该层个股，标签带封板形态与 ST 标记
- **行业 / 概念分布**（Top15 横向条形图 + 可点选表格）：点行即按该行业/概念过滤明细表，
  筛选在**本地**完成、不重新请求；与选股页一样，分布基数不受该筛选本身影响
- **明细表**：连板 / 代码 / 名称 / 封板 / 二级行业 / 概念 / 收盘价 / 涨跌幅 / 成交额(亿) /
  流通市值(亿) / 涨跌幅限制 / 板块，12 列全部可排；点任意行打开 K 线抽屉（复用选股页的抽屉）
- **日期控件**：可选范围 = 本地全历史（1991-01-02 ~ 最新，共 8786 个交易日），
  右侧「最新」一键回到最新交易日；**选到非交易日会明确报错并给出范围**（不像选股页做吸附，
  避免「以为看的是 X 日、其实看的是 Y 日」）
- 实测耗时：**0.05 ~ 0.16 s**（含 2015 / 2018 / 2022 等历史日期），因为连板计数是
  「类别层窗口 + 向量化分段」，不逐股循环

**ST 5% 口径默认关闭**，这一条是本机数据实测的结论，不是省略：

| 观测 | 值 |
|---|---|
| 名称含 ST 的主板个股 | 144 只 |
| 其中出现过「日内最高价 > 前收 × 1.05」的 | **141 只（97.9%）** |
| 这些个股 `high / 前收` 的 p99.9 | **≈ 1.10** |
| 单只违例天数占其交易日 | 8% ~ 37% |

也就是说这批本地行情里**主板 ST 股的涨跌幅限制也是 10%**。套用 5% 会把涨幅 5%~10%
的普通交易日错判成涨停 —— `2026-06-01` 一天就从 120 只变成 168 只（多出 48 只）。
兄弟应用的口径也写明「ST 股按常规板近似」。因此页面上的「ST 按 5% 判定」开关
**默认不勾**；只有行情源确实带 5% 带宽时才需要打开。恢复脚本：`packaging/streak_test.py`。

### 2.11 板块交集（二级行业 ∩ 概念）

侧栏「板块交集」页。回答的是一个和选股、连板都不同的问题：
**哪些票同时属于这些二级行业、又属于这些概念** —— 纯板块归属的集合运算，与量价无关。

集合定义（都限定在「锚点日有行情、且通过轻量过滤」的候选集内）::

    A = 二级行业命中选中行业的标的（多选 = 并集；不选 = 全集）
    B = 概念命中选中概念的标的（可任一 / 全部；不选 = 全集）
    结果 = A ∩ B

- **行业侧只有并集**：一只标的的二级行业是**单值**，选两个行业求交恒为空，
  所以行业不给「全部命中」选项（给了反而误导）。概念是列表，故 `any` / `all` 都有意义。
- **双圆文氏图**：`A 独有 / A∩B / B 独有` 三个数并排，左右圆下方标出 A、B 的规模与口径，
  一眼看出交集是把哪一侧收窄了。不用 ECharts —— 两个圆用纯 SVG 更短也更可控。
- **两个多选器**（左行业、右概念）：都是「点标签即选 / 再点取消」，
  顶部已选区始终占位（空时给一句说明），**避免点选时整页上下跳**。
  - 行业：按一级行业分组展示，每个标签带**静态成员数**（`/api/industries` 的 `l2_counts`），
    128 个行业排在一起时能一眼看出哪个是主流
  - 概念：269 个，无搜索词时只渲染前 120 个（按成员数降序），搜索时不设上限
- **点选即算**：改任一条件后 220ms 防抖自动重算（后端实测 0.05~0.2s），
  不必反复按「求交集」；按钮仍在，可以手动强制刷新
- **交集为空时给「下一步往哪调」**：把「A 里最常出现的概念」和「B 里最常出现的二级行业」
  两组标签回给前端，点一下就并入对应一侧并立即重算 —— 空结果本身没法自查，
  这两组数字就是自查的入口
- **明细表**：代码 / 名称 / 二级行业 / **命中概念**（本次选中的那几个）/ 概念数 /
  收盘价 / 涨跌幅 / 成交额(亿) / 流通市值(亿) / 板块，10 列全部可排（默认成交额降序）；
  点行打开 K 线抽屉，抽屉里照旧能「加入计划 / 加入追踪」
- **明确报错而不是静默空结果**（这类失败最难自查）：
  未知行业名 / 未知概念名、两侧都不选、空板块、**空交易所**、越界日期，全部返回
  `ok=false` + 原因；`/api/intersect` 的业务错误走 HTTP 200，不是 500
- **口径透明**：`conditions` 写明锚点日、候选规模、两侧口径、板块/交易所/ST/成交额/市值，
  `warnings` 提示概念归属缺失只数、行业归属缺失只数，以及**回溯历史日期时板块成分仍是
  本地文件的「当前」成份**（是「用今天的板块看历史行情」，不是历史快照）
- 实测：全市场 5605 只 → 0.05 ~ 0.2s

### 2.12 板块看盘（概念板块 / 行业板块）

按行情软件的看盘习惯做的四宫格：**顶部一排类别 tab，下面上半左右两栏列表、下半左右两张
「K 线 + 成交量 + MACD」**。左栏点板块 → 右栏出成分股 + 下面出板块指数 K 线；
再点成分股 → 右下图出个股 K 线。

板块列表 9 列（代码 / 名称 / 涨幅 / 成交额 / 量比 / 换手 / 涨跌家数 / 涨停 / 成分），
**没有「类别」列** —— 类别已由 tab 选定的模式表达，整列同值只是噪音。

界面上的「板块类别」是**页面顶部一个两段 tab**，只保留能做题材看盘的两类：
**概念板块（268 个有成分）与行业板块（132 个）** —— tab 上的数字就是切过去之后的列表行数。板块池本身是通达信板块指数表 `T0002/hq_cache/tdxzs.cfg` 的
**全部 604 条**，另外两类不进主视图（`/api/board_panel` 仍支持传 `category=地区|风格`，
`/api/board_catalog` 也仍返回完整四类，只是 `categories[].primary` 标出哪两类是主视图）：

| 类别 | 类型码 | 数量 | 有成分股 | 成分来源 | 主视图 |
|---|---|---|---|---|---|
| 行业 | 2 | 145 | 132 | `tdxhy.cfg` 的 **T 码**（前缀聚合）+ `incon.dat#TDXNHY` 名称表 | ✅ |
| 概念 | 4 | 269 | 268 | `infoharbor_block.dat` 的 `GN_` | ✅ |
| 风格 | 5 | 158 | 152 | `infoharbor_block.dat` 的 `FG_`。是**因子/盘口指标**（`昨日涨停`/`基金重仓`/`破净资产`），不是题材 | ✗ |
| 地区 | 3 | 32 | 0 | 本地无归属文件 → **只有指数行情** | ✗ |

tab 上的数字用的是 **`n_members`（有成分的板块数）**，所以和勾着「仅有成分」
时的行数一致（`概念板块 268` / `行业板块 132`）。

每个板块的指数代码都是 `880xxx`，且**本地 604/604 都有日线文件**（`vipdoc/sh/lday/`），
所以有没有成分股都能画 K 线。索引由 `boards.py` 解析并落盘 `data/boards.json`（约 1 MB，
二次加载 16 ms）。

列表指标分两部分拼成：

| 指标 | 来源 |
|---|---|
| 涨幅 / 现价 / 成交额 / 量比 | **板块指数自己的日线**（`.day` 尾部 seek 读取） |
| 涨跌家数 / 涨停跌停数 / 成分均涨幅 / 换手率 | **成分股在锚点日聚合**（一次 `groupby`，不做逐板块循环） |

**为什么行业走 T 码而不是本项目的 X 码**：`tdxhy.cfg` 每行同时带 T 码（通达信行业）与
X 码（研究行业）。项目其余部分用 X 码（128 个二级行业，见 [2.2](#22-二级行业分类)），
但 `tdxzs.cfg` 里行业板块的 145 个名字**只和 T 码名称表对得上**：实测交集 132/145、
覆盖 5584/5585 只股票；换成 X 码名称只对上 47 个。剩下 13 个（`TDX 交运` / `TDX 信息` /
`传媒娱乐` 这类通达信一级别名与旧行业名）本地没有归属文件，只提供指数行情。

**行业板块必须按 T 码前缀聚合**：T 码是层级码（`T01` 一级 / `T0101` 二级 / `T010101` 三级），
而每只股票的归属码实测都是**三级**码。若等值匹配，「煤炭」（`T0101`）、「石油」（`T0103`）
这类**二级**板块会一个成员都没有；按前缀聚合后它们才拿到整条下级的成分
（煤炭 32 只，其中煤炭开采 `T010101` 25 只 ⊂ 煤炭 32 只），这也是通达信行业指数的口径。

实测进入匹配集的 132 个行业板块按层级分布是 **一级 0 / 二级 56 / 三级 76** ——
**没有一级**：13 个一级 T 码（`T01`…`T13`）在 `tdxzs.cfg` 里叫「TDX 交运」这类别名，
与 `incon.dat` 的名称对不上，正好就是 `verify.industry_unmatched` 那 13 个，
它们只提供指数行情。

几处口径与已知边界：

- 涨跌停判定**完全复用连板梯队那一套**（[2.10](#210-连板梯队) / `limits.py`）：基准价取前一根
  收盘、上市首日剔除、ST 5% 默认关闭 —— 与连板梯队逐条一致。因此 `summary.limit_up_stocks`
  可以和 `/api/streaks` 的 `metrics.limit_up` **直接对上**（2026-09-24 两边都是 52）。
- `summary` 里的涨停 / 跌停数是**全市场去重**口径；板块级的 `n_limit_up` 是「该板块内有几只
  涨停」，跨板块相加会重复计同一只股，别拿它求和。
- `summary` 在 `limit` 截断**之前**统计，否则「604 个板块里几个在涨」会被首屏几十行带偏。
- **换手率** = Σ成分股成交量 ÷ Σ流通股本（股本取自本地 `gbbq`），缺股本的股票不计入分母。
- 锚点日**锚在全市场交易日**上（与选股 / 连板一致），停牌板块不会拿自己的最后一根冒充当日行情；
  这类板块 `pct` 给 `null` 并列进 `stale`（2026-09-24 有 5 个，都是通达信自算的属性板块，
  如「昨ST连板」「业绩预升」，其指数文件在该日无数据）。
- 成分股列表只列**当日有行情**的（停牌不进列表），`n_total` 是静态成分数、`n_suspended`
  是两者之差。
- **`tdxzs.cfg` 第 6 列不一定是名字**：145 个行业板块那列放的是 **T 码**（`T0101`、
  `T030203`），32 个地区板块放的是**序号**（`1`、`2`…），只有概念 / 风格是真的全称
  （其中 53 个与第 1 列的简称不同，那些要保留）。所以 `boards.py` 见到纯数字或 `T`+数字
  就回退用第 1 列的名字，否则界面上会冒出一个叫「T030203」或者叫「1」的板块。
- 换手率、量比等指标依赖「前 N 根」，所以板块指数读的是**文件尾部**而非整读：
  604 个板块齐扫约 20 ms（整读一遍要 0.9 s）。缓存键带**已读根数** —— 板块列表只要 22 根，
  K 线图要 200+ 根，只按 mtime 命中会把 22 根那份交给 K 线图（K 线图会只剩一小截）。

### 2.13 自选板块（通达信 `T0002/blocknew`）

看**你自己在行情软件里手工维护**的那批自选板块。与 [2.12 板块看盘](#212-板块看盘概念板块--行业板块)
的区别很关键：那边读的是通达信**自带**的行业 / 地区 / 概念 / 风格分类（`hq_cache/` 下的一套
`.cfg` / `.dat`），这边读的是**你自己的自选板块**（`T0002/blocknew/`），会随你增删而变。

页面结构：**顶部下拉框选一个自选板块 → 两张分布卡（二级行业分布 / 概念分布）→ 成员股明细表**。

```
T0002/blocknew/
    blocknew.cfg      N 条记录  板块「显示名 + 成分文件名」（变长记录，见下）
    *.blk             N × 9 B  每个板块一个文件，7 位 ASCII 代码一行
    blocknew.clr      1600 B   每个板块的显示颜色，本工具不解析
    zxg.blk / tjg.blk          通达信内部用（添加自选 / 自选股），界面上不显示
    zxgmore.dat       11120 B  自选股附加属性，二进制，本工具不解析
```

#### `blocknew.cfg` 的记录边界不是定长

文件里是「GBK 中文显示名 + ASCII 文件名」**交替出现的字段流**，每个字段以 `\x00` 结尾并补齐到
边界，但**补齐长度不固定** —— 中文名占 2 字节/字，名字长短不同，记录的物理边界就会落在字段中间。

所以**不能按「50 字节一条记录、25 字节名 + 25 字节文件名」切**：那样会把名字拦腰截断
（实测「集合竞价大量」被切成 `集合` + 下半截跑到下一条记录尾部）。

正确做法是**忽略物理边界**，按「连续非 0 字节段」切出**字段流**，再**两两配对**：第 1 段是显示名
（GBK 解码），第 2 段是文件名（ASCII），依此类推。配对关系来自文件结构本身的交替性，不依赖任何
长度假设，对中文名长短不敏感；字段数为奇数时丢掉最后一段（宁可少一个板块，也不错位成假名字）。

实测段数恒为板块数的 2 倍、**每个文件名全部命中磁盘同名 `.blk`**，零错配。

#### `*.blk` 的 7 位代码

每行 **7 位 ASCII**：首位是**市场码**，后 6 位是股票代码：

| 首位 | 交易所 | 实测行数 |
|---|---|---|
| `0` | 深市 `sz` | 1094 |
| `1` | 沪市 `sh` | 1206 |
| `2` | 北交所 `bj` | 4 |

文件布局是「`\r\n` + 7 位代码」逐行重复、**无尾换行**，实测字节数 **= 行数 × 9**
（不是 ×7 —— 行间那两个 CRLF 也在文件里；首个 CRLF 与「无尾换行」正好抵消）。空板块
（`2-12.blk` / `zxg.blk`）是 **0 字节**。

文件里除了数字与 CRLF **没有别的字节**（23 个文件全部零杂字节），因此「把数字全提出来按 7 位切」
与「按行解析」完全等价 —— 而前者对「有没有行尾换行」「是 LF 还是 CRLF」都不敏感，更稳。

实测 23 个 `.blk` 共 **2304 行**、去重后 **1603 个代码**，用 `tdx_reader.is_a_share()` 过滤后
**仍是 1603 个（零剔除）**，按首位 / 按后缀两种口径统计的行数折算后**逐项相等**，证明市场码
映射无误（错一位就会把整个板块搬到别的交易所）。按板块分（`is_a_share` 后）主板 1376 /
创业板 143 / 科创板 80 / 北交所 4。

#### 板块清单口径

界面上列出的板块数**等于 `blocknew.cfg` 里的记录数**（会随用户增删而变），其中多数有成分。磁盘上的 `.blk` 可能比 cfg
多两个 —— `tjg.blk`（140 只）/ `zxg.blk`（0 只），它们是通达信内部用的，界面上不显示，
所以不进清单；但**仍解析并记进 `meta.verify.orphan_files`**，方便排查「为什么界面少一个板块」。

清单里每项都带两个标识：`key` 是 `.blk` 文件名去后缀（ASCII，前端引用用），`name` 是
通达信里显示的 GBK 中文名。有的板块用户没改名，显示名就等于文件名（`60-11-14` / `MACD_1-23`）。
接口**两种都能传**（`/api/watch_block_panel?block=ZFPZ` 和 `?block=窄幅盘整` 等效）。

**下拉框只显示 `显示名 · 成员数`**（`均线纠缠_初选 · 193` / `60-11-14 · 231`）：
不拼 `.blk` 后缀、也不重复文件名 —— 文件名对用户没有意义，拼上去既占宽度又容易被原生
`<select>` 截断（实测未精简时选项要 238px，精简后 150px 即够）。
成员数为 0 的板块保留在列表中但**置灰不可选**（显示 `2-12 · 空`），
因为用户可能刚建好还没往里加股票，直接隐藏会让人以为工具没读到。
下方「条件栏」同理：**只有显示名 ≠ 文件名时**才补一个 `（JXJC_CX）`，
便于在用户改了通达信里的显示名之后仍能对上磁盘文件。

#### 动态扫描：在通达信里改了板块，**不用重启服务**

自选板块是用户随时会动的（新建一个板块试策略、删掉用不上的、往板块里加减股票）。
所以这条链路上**没有任何一处依赖「启动时读一次」的快照**：

| 层 | 做法 |
|---|---|
| 索引层 `WatchBlockIndex.refresh()` | 每次调用都重算 `_signature()`，**变了才重建**（没变几乎零成本） |
| 服务层 `service.watch_block_catalog(refresh=True)` | 默认 `refresh=True` 先刷指纹，异常则退回现有索引（不让清单接口整个挂掉） |
| 前端 `switchTab('watchblock')` | **每次切过来都重扫**清单（`loadWatchBlocks({keep:!first})`） |
| 前端按钮「重新扫描板块」 | 手动强制一次，并弹 toast 告诉用户**这一趟到底有没有变化**（没变化也反馈，免得用户以为按钮失效而反复点） |

`_signature()` 覆盖 **`blocknew.cfg` + 目录下每一个 `.blk`** 的 `size`/`mtime`（实测 24 个文件、
`DirEntry.stat()` 约 **0.34ms**），所以放进**每次请求**做是安全的。

指纹必须覆盖全部 `.blk`，不能只盯 `cfg`：用户「往已有板块里加减股票」时 **cfg 一个字节都不变**，
只改了那个 `.blk`。反过来，「只放一个 `.blk` 但没在 cfg 里登记」的板块**不会进清单** ——
`cfg` 是清单的权威来源（通达信自己会同步写两处），这条由回归测试第九节钉住。

端到端实测（真实通达信目录，**服务全程不重启**）：

```
基线                             total=11  source=cache
新增 ZZDYNT（写 cfg + .blk）      total=12  source=parsed   ← 自动发现
再调一次                         total=12  source=cache    ← 不重复解析
删掉                             total=11  source=parsed   ← 自动还原
```

前端也实测过同一趟：页面**切过去就已含**新板块（`动态测试板块 · 58`），点「重新扫描板块」保留
当前选中项、不跳回第一个。

#### 分布卡与「基数不随筛选变化」

两张分布卡（二级行业分布 / 概念分布）复用**选股页那一套 chip 交互**
（见 [2.1](#21-选股)）：点标签即筛选、再点取消、可叠加多选。

统计基数 `summary_base` 是**该板块当日有行情的成员数**，也就是**在应用行业 / 概念筛选之前**
取的快照 —— 这样点掉一个行业之后，其余 chip 不会连带消失，用户可以连续切换着看。
这是选股页踩过的同一个坑，两个页面用同一个不变量：

```
summary_base   = 该板块成员 ∩ 当日有行情（− 成交额 / ST 过滤）
industry_summary / concept_summary  都按 summary_base 统计
matched        = summary_base 再经行业 / 概念筛选后的只数
```

自校验（`packaging/watchblock_test.py`）会逐条核对：**分布卡里某个标签的计数，必须等于
「按该标签过滤后的行数」** —— 两边口径一旦分叉，这个等式立刻不成立。

#### 几处口径与边界

- **涨跌停**：`limit` 字段走 `limits.py` 同一套判定（锚点日前收 × 该股自己的涨跌幅限制、
  上市首日剔除），与连板梯队 / 板块看盘的成分股一致。
- **成员股只列当日有行情的**（停牌 / 未上市不进明细），`n_total` 是 `.blk` 里的静态成员数、
  `n_suspended` 是两者之差。
- 「命中概念」列在**没有概念筛选时**展示该股最主要的 3 个概念（而不是整列 `—`）；有筛选时
  只显示真正命中的那几个。
- 点明细行**开 K 线抽屉**，复用选股页的抽屉（含计划买入/卖出价、加入计划 / 追踪）。
- **未知板块 / 未知行业名 / 未知概念名一律明确报错**，不静默返回空结果 —— 打错一个字就得到
  空表是最难自查的失败。
- 缓存落盘 `data/watch_blocks.json`，指纹 `sources` = 解析版本 + `blocknew.cfg` 的
  size/mtime + **每个 `.blk`** 的 size/mtime（只盯 cfg 会漏掉「新加了一个板块文件但没改 cfg」）。
  改动解析逻辑要 +`PARSE_VERSION`。

接口：`/api/watch_blocks`（清单）、`/api/watch_block_panel`（面板数据，参数名 `block`）。
回归：`python packaging/watchblock_test.py`（82 项断言）。

## 3. 数据来源与口径

- 目录布局：`{tdx_dir}/vipdoc/{sh,sz,bj}/lday/{market}{code}.day`
- `.day` 为**定长 32 字节**记录：`date/open/high/low/close` 为 `uint32`（价格单位「分」，
  ÷100 得元），`amount` 为 `float32`（元），`volume` 为 `uint32`（**股**）
- 股票池：仅 A 股正股，剔除指数、ETF/LOF、可转债、B 股
  （沪 `600/601/603/605/688/689`、深 `000/001/002/003/300/301`、京 `43/83/87/88/92`）
- **不复权**：本地通达信日线是不复权数据，页面「选股条件」中已明示
- 股票名称：解析 `T0002/hq_cache/{shs,szs,bjs}.tnf`，缓存到 `data/stock_names.json`，
  对本地标的覆盖率约 **97%**（未命中主要是已退市个股与可转债）
- 缓存：`data/cache/bars.parquet` + `bars_meta.json`。**默认缓存全历史**
  （`cache_bars: 0`，每只从 `.day` 第一根读起），见 [3.1](#31-行情缓存与内存口径)
- **流通股本**：解析 `T0002/hq_cache/gbbq`（股本变迁，加密二进制，20.0 万条），
  取每只标的 `category == 5`（股本变化）**最后一条**记录的「变动后流通股本」，
  缓存到 `data/float_shares.json`。对 5602 只 A 股覆盖 **100%**。
  详见 `shares.py` 顶部注释（含与公开数据的核对表）。
- **概念板块**：解析 `T0002/hq_cache/infoharbor_block.dat`（板块成分）+ `tdxzs.cfg`
  （概念口径，类型码 4），缓存到 `data/concepts.json`。269 个概念、46529 条归属，
  对 5602 只 A 股覆盖 **97.0%**。详见 [2.3](#23-概念分类) 与 `concepts.py` 顶部注释。

### 3.1 行情缓存与内存口径

`config.json` 的 **`cache_bars`** 决定每只股票缓存多少根 K 线：
`0` 或负数 = **不限制，读入 `.day` 的全部历史**（默认）；正的 N = 只留最后 N 根。

全历史下全市场是 **17,012,754 行**（5605 只，平均 3035 根，最长 8591 根，
最早可回溯到 1991-01-02），所以缓存列一律走**收缩 dtype**（见
`tdx_reader.CACHE_DTYPES`）。收缩前先核算过精度，不是随手降的：

| 列 | dtype | 为什么安全 |
|---|---|---|
| `code` | `category`（int16 码） | 5605 个类别只占 2 字节/行；换 object 字符串约 54 字节/行，**单这一列差 ~900MB** |
| `date` | `int32` | YYYYMMDD 最大 8 位 |
| `open/high/low/close` | `float32` | 源是「分」网格（0.01 元），实测最大收盘价 3275 元处 ULP 仅 2.4e-4，`round(x,2)` 不跳变 |
| `amount` | `float32` | 源本身就是 float32；最大 1.41e11 元处 ULP 16384 元，而展示是「亿」保留 3 位（1e5 元分辨率） |
| `volume` | **`uint32`** | 源就是 uint32（单位「股」），**无损**。**不能降成 float32** —— 实测最大 4.17e9 股处 ULP 是 256 股，会让「手」的显示值偏 1~2 手 |
| `pct` | `float32` | 相对量，相对误差 ~6e-8；但**计算**时仍用 float64 做完再降精度 |

实测（本机 5605 只 / 17.0M 行）：

| 指标 | 数值 |
|---|---|
| `bars.parquet` | **360.4 MB** |
| 内存长表（`memory_usage(deep)`） | **578.9 MB** |
| 进程工作集 | ~1.4 GB |
| 重建耗时 | **18.8 s**（原 260 根口径约 8 s；时间主要在多出来 11.7 倍的建表/落盘，文件 IO 本来就整读）|

**`bar_index` / `bar_total` / `ma_vol` / `vol_ratio` 都不落列**，按需实时算：

- `bar_total`（截至某日的 K 线根数）→ `_category_bar_counts()`，只在 5605 个
  类别上做一次 `searchsorted`，结果 22 KB。若落列是 1700 万行 int64（**136 MB**）。
  注意它按**锚点日**取值，而不是「整段历史的长度」—— 否则回看 2022 年时，
  2022-05 才上市的票会误判为「K 线充足」。
- `ma_vol` / `vol_ratio` → `_attach_volume_stats()`。原先是对整张长表
  `groupby().transform(rolling())`，全历史下要为 1700 万行建两个新列（**136 MB**）
  并跑一次全市场 rolling；其实选股只用到目标日期那几行，所以改成只对命中行
  求和（约 5605×20 = 11 万个元素），**结果在 float64 下逐值精确**。
- `bar_index` 全项目无人使用，直接不存（需要时可按同样方式从 slice 序号导出）。

选股过滤也改在**类别层**做：`split_code` / 板块判定只对 5605 个类别算一次掩码，
再用 `cat_ok[cat_codes]` 展开成行级布尔，避免对 1700 万行逐行映射。
历史日期选股实测 **0.11 s**。

## 4. 读取层：pytdx 为主，向量化为辅

`tdx_reader.py` 提供两条读取路径，**归一化后结果逐字段完全一致**：

| 模式 | 实现 | 全市场(5600 只)耗时 |
|---|---|---|
| `pytdx` | `pytdx.reader.TdxDailyBarReader.get_df_by_file` | ≈ 60 s |
| `fast` | numpy `frombuffer` 直接映射定长记录（默认） | ≈ **8 s** |

两点必须注意（已在代码中处理，改动时勿踩）：

1. **pytdx 返回值与文件原始值不同**：行索引名是 `date`（不是 `datetime`）；
   价格已 ÷100（元）；**成交量额外 ÷100**（返回「手」），需 ×100 还原为「股」。
2. **pytdx 覆盖不到科创板与北交所**：`688xxx.SH`、`8xxxxx.BJ` 会抛
   `Unknown security exchange`。`fast` 模式与 pytdx 的失败回退都能正常读取。

向量化路径读取的字节布局与 pytdx 完全相同，因此不存在「两套口径」问题。
页面右上角 **数据自检** 会随机抽样，用 pytdx 与向量化两路解析同一批文件并逐字段比对，
返回 `checked` / `mismatches`。当前实测：**24/24 完全一致，0 处差异**。

`--reader pytdx` 可切换为全量走 pytdx（更慢，但完全不依赖向量化路径）。

### 5.1 前端资源指纹与缓存策略

本地工具反复出现的一类「假故障」：**改了 `static/` 但页面没变化**。根因是浏览器缓存 ——
没有 `Cache-Control` 的响应会被浏览器启发式缓存，重新打包后旧标签页可能继续跑旧的
`app.js`。被它坑过一次：`/api/trade_dates?n=0` 已经在返回 8786 个交易日（首个 1991-01-02），
但页面里跑的还是老的 `?n=250`，于是「指定日期」控件的下界仍卡在 2025-09-12 ——
看起来像"后端没改"，实际是前端没换。

三道防线，缺一道旧标签页就可能继续跑旧脚本：

| 防线 | 做法 |
|---|---|
| 响应头 | `/api/*` 与首页 HTML → `Cache-Control: no-store`；`/static/*` → `no-cache, must-revalidate` |
| URL 指纹 | `/` 返回 HTML 时把 `__ASSET_VER__` 替换为 `ASSET_VERSION`（app.js + style.css + index.html 三者内容的 md5 前 10 位），页面实际请求 `/static/app.js?v=cc93d5b69e`。前端一变地址就变，浏览器不可能命中旧条目 |
| 页面自检 | `GET /api/version` 暴露同一指纹；`app.js::loadVersion()` 加载时记下它，之后每 20 秒、以及每次切回该标签页时比对一次，不一致就在顶部弹出橙色横幅（`#staleBanner`）提示刷新 |

**改了前端后的正确姿势**：重新打包 → 重启 exe → 已打开的页面按 F5（保险起见 Ctrl+Shift+R）。
普通刷新即可，指纹会自动绕开所有旧缓存条目。

## 8. 已知限制

- 选股基于**日线**，信号在收盘后才成立；买入价默认为放量日收盘价，请按自己的
  交易规则调整
- 本地数据为**不复权**，长期回看时除权股的价格与均量会有跳变
- 名称表未覆盖的少数标的（已退市/可转债）在列表中显示为空名
- 有 38 只 A 股（多为退市/长期停牌）在 `tdxhy.cfg` 里没有行业标记，其「二级行业」显示为 `—`
- **167 只 A 股在本地板块文件里没有任何概念归属**（新股、退市边缘、长期停牌等），
  「概念」列显示 `—`；用了概念筛选时它们会被排除，页面会提示「因缺分类被过滤 N 只」
- 概念分类来自通达信本地板块文件，**只有通达信客户端同步过板块数据才是最新的**。
  文件变化（mtime/size）时会自动重建 `concepts.json`，也可调 `POST /api/concepts/reload` 强制刷新
- 概念之间存在天然重叠（一只票平均 8.55 个概念、最多 49 个），**概念数多不等于题材强**；
  本工具只做归属展示与筛选，不做题材强度打分
- **流通股本是「最近一次股本变化」后的数值**，不是逐日历史股本。因此用「指定日期」回看
  较早的交易日时，市值用的是**当前**股本而非当日股本，存在偏差（复权/送转后尤其明显）。
  23.7% 的标的上一次股本变化在 2025 年之前——这是股本本身没变，不是数据陈旧
- 本地 `gbbq` 只有在通达信客户端**下载过盘后数据**时才会更新。股本变动后需在客户端同步一次；
  `float_shares.json` 缓存在检测到 `gbbq` 的 mtime/size 变化时会**自动重建**，
  也可调 `POST /api/shares/reload` 强制刷新
- 二级行业用的是**通达信研究行业**口径，与申万二级、中信二级在个别标的与名称上会有差异
  （例如白酒：本工具一级「食品饮料 / 二级 酿酒 / 三级 白酒」）
- 放量倍数用的是**成交量（股）**，不是成交额；如需按金额口径，改
  `service.py::_attach_volume_stats` 里取的 `volume` 字段即可
- **连板梯队的涨停判定有几处无法靠本地数据修掉的偏差**（页面 `warnings` 里也会提示）：
  - **除权日**前收用的是未复权收盘价，除权日它会偏高 → 涨停价算高 → **可能漏判除权当天的涨停**
  - 创业板 / 科创板上市**前 5 个交易日**、北交所**首日**均无涨跌幅限制，本口径只剔除上市首日，
    所以这些标的上市第 2~5 天的大涨可能被算成涨停；停牌复牌（重大资产重组等）无限制的当天同理
  - ST 按**当前名称**判定，无法回溯「某历史日期时它是否已 ST」
- **ST 5% 口径默认关闭**，因为本机行情实测主板 ST 股的日内带宽也是 10%（详见
  [2.10](#210-连板梯队)）。若你的行情源确实带 5% 带宽，勾上页面上的开关即可
- **板块交集的行业 / 概念都是「当前」归属，不是历史快照**：本地板块文件只有一份，
  所以用「指定日期」回溯时，是「**用今天的板块成分看历史行情**」。查历史日期的板块交集时
  页面会明确提示这一点（这不是 bug，是本地离线数据的固有边界）
- 板块交集里**不选行业 = A 是候选全集**、不选概念 = B 是候选全集，两侧都不选则直接报错；
  想要「某行业里概念最多的票」这类偏序问题，可以先只选行业、再看「概念数」列排序
- 工具只做筛选与记录，**不构成任何投资建议**

## 9. 打包成 exe (Windows)

### 9.1 怎么打

```bash
pip install pyinstaller                  # >= 6.0
python packaging/build.py                # 单文件 → dist/stock_picker.exe
python packaging/build.py --onedir       # 目录版 → dist/stock_picker/stock_picker.exe
python packaging/build.py --both         # 两种都出
python packaging/build.py --windowed     # 隐藏控制台窗口（默认保留，便于看日志）
```

产物目录：

```
dist/
├── stock_picker.exe        单文件版，拷走这一个文件就能用
├── config.json             配置模板（已存在则不覆盖）
└── 使用说明.txt             给最终用户的说明
```

### 9.2 目录分离是打包的关键

打包后**必须**把「代码/静态资源」和「可写数据」分开放，否则计划与追踪会丢：

| 变量 | 源码运行 | 打包运行（onefile） | 用途 |
|---|---|---|---|
| `RESOURCE_DIR` | `stock_picker/` | PyInstaller 解包临时目录 | 代码 + `static/`，**只读** |
| `APP_DIR` | `stock_picker/` | **exe 所在目录** | `config.json` + `data/`，**可写** |

onefile 模式的解包目录（`sys._MEIPASS`）**退出即删**。如果 `DATA_DIR` 还指向那里，
双击 exe → 加自选 → 关窗口，`stock_picker.db` 就没了。所以
`config.py` 里用 `sys.frozen` 判断，把 `APP_DIR` 切到 `sys.executable` 所在目录。

想换数据位置（或复用源码模式已有的数据）就设环境变量：

```bat
set STOCK_PICKER_HOME=F:\source\stock_rsi\stock_picker
stock_picker.exe
```

这样 `APP_DIR` 就指向源码目录，**沿用原来那份 `config.json` 与 `data/stock_picker.db`**，
已有的计划/追踪直接可用。

### 9.3 打包脚本里那些必须显式声明的东西

PyInstaller 靠静态分析收集依赖，下面几处它看不到，漏了就是运行时报错：

| 位置 | 为什么要显式加 |
|---|---|
| `uvicorn.loops.*` / `uvicorn.protocols.*` / `uvicorn.lifespan.*` | uvicorn 用**字符串查字典**选实现类，不 import |
| `pyarrow` / `pyarrow.parquet` | pandas 的 parquet 引擎是运行时按名字 `import_optional_dependency` |
| `pytdx.reader.*` | `shares.py` 里在**函数内** import，且直接取子模块的类 |
| `--add-data stock_picker/static` | 静态资源不是 .py，不会被自动收集 |
| `multiprocessing.freeze_support()` | 没有它，冻结后子进程会反复重开 exe |

另外排除了一批确定用不到的大件（`matplotlib` / `scipy` / `tkinter` / `pandas.tests` …）。
原则是**只剔除任何代码路径都不会 import 的**，`pandas`/`numpy` 核心与 `pyarrow.parquet`
一律保留——宁可大 20MB，也不要在用户机器上炸 ImportError。

### 9.4 图标

`packaging/make_icon.py` 用**纯 Python** 写 `.ico`（不依赖 Pillow / cairosvg）：
按 32×32 设计稿（圆角蓝底 + 三根白色 K 线，与 `static/favicon.svg` 同款）
4×4 超采样渲染，输出 16/24/32/48/64/128/256 七种尺寸。
构建时若 `.ico` 不存在会自动生成。

### 9.5 打包后怎么验

四个脚本，都只用标准库，可独立运行：

```bash
# 1) 端到端冒烟：启动预加载 / 静态资源 / HTML 结构体检 / 选股 / K 线 / 计划追踪 / 备份
#    开头会先等「启动即预加载」跑完，再逐项断言

# 2) 持久化：写入 → taskkill /F 强杀 → 重启 → 逐条复核

python packaging/persist_test.py dist/stock_picker.exe 8779

# 3) 分布卡基数回归（源码态，不用起服务；43 项断言）
python packaging/summary_base_test.py

# 4) 连板梯队专项回归（源码态，不用起服务；64 项断言）

`persist_test.py` 是打包环节**最该跑的一个**：它专门强杀进程（不走优雅关闭），

> ⚠️ 两个测试脚本都**只允许动自己写入的数据**。`persist_test.py` 以前直接跑在 `dist/`
> 上、清理时遍历接口返回的全部条目逐个删除 —— 那会把用户自己建的计划一起删掉。

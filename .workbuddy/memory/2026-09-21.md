## 本次攻克的三个技术难点（可复用）

### 1. 通达信 `.tnf` 股票名称表的二进制格式（此前未知，现已破解）

`T0002/hq_cache/{shs,szs,bjs}.tnf` 是标准名称表，结构为：

- 文件 = `N × 360` 字节定长记录 + **50 字节尾部**（`len(data) - 50` 必须能被 360 整除）
- 每条记录内：**名称在 `[81:89]`**（8 字节 GBK，`\x00` 补齐）
- **代码**：从名称位置向前 40 字节窗口里，取最后一段连续 6 位数字
- 记录锚点从**文件偏移 0** 开始（不是从 50 开始），这点容易搞错

实测 shs 27921 条 / szs 24274 条 / bjs 384 条全部有效，对本地 vipdoc 覆盖率 **96.9%**
（未命中主要是已退市个股与可转债）。名称含全角字符与空格，如 `万 科Ａ`，**不要 strip 内部空格**。

### 2. pytdx 与文件原始值的量纲差异（再次确认，写入了新代码）

- `.day`：价格 int32「分」÷100 得元；成交量 uint32「**股**」
- pytdx 返回：价格已 ÷100；**成交量额外 ÷100（返回「手」）**，需 ×100 还原为股
- pytdx 的行索引名是 `date`，不是 `datetime`
- **pytdx 不支持 688 科创板 / 8xxxxx 北交所**，抛 `Unknown security exchange`

### 3. 性能：pytdx 61s → 向量化 8s，且两者结果逐字段一致

| 路径 | 实现 | 全市场 5602 只耗时 |
|---|---|---|
| `pytdx` | `TdxDailyBarReader.get_df_by_file`（Python 循环，GIL 受限） | ≈ 60 s |
| `fast`（默认） | `np.frombuffer(raw, dtype=DAY_DTYPE)` 直接映射定长记录 | ≈ **8 s** |

**关键结论**：`.day` 是定长 32 字节记录，字节布局与 pytdx 完全一致，因此向量化路径
不是「另一套口径」。已内置 `verify_readers()` 抽样自检，实测 **24/24 逐字段 0 差异**
（日期、OHLC、成交量、成交额）。UI 上有「数据自检」按钮。

> 注意：**不要**用 ProcessPoolExecutor 并行 pytdx 来提速（Windows spawn + uvicorn 下易挂）；
> 直接上向量化即可，快 117 倍。

## 20:24 结果表增加表头排序

**需求**：「选股结果可以按涨跌幅排序」。做成**13 个表头全部可点**，不止涨跌幅。

**关键设计：排序只改渲染顺序，不动 `state.rows`。**
`sortOrder()` 返回 `state.rows` 的**下标数组**，渲染时 `order.map(i => ...)`，
行上的 `data-i` 仍是 `state.rows` 原下标。这样行内买卖价输入框、点行开抽屉、
加入计划/追踪全都无需改动 —— 如果直接 `state.rows.sort()`，行下标会全部错位，
用户填过的买价会串到别的股票上。实测：把某股买价改成 99.99 再换列排序，
该股移到第 179 行、买价仍是 99.99，全表仅此一处。

**要点**
- 默认 `{key:'vol_ratio', dir:'desc'}`，与后端顺序一致，首次进入不做二次重排
- 同列再点反向；数字列首次降序、文本列首次升序（中文用 `localeCompare('zh-Hans-CN')`）
- 缺值恒沉底（不随方向翻转）；同值 `return a-b` 保证稳定
- 导出 CSV 也走 `sortOrder()`，与屏幕顺序一致（原来直接遍历 `state.rows`，会不一致）
- `doScreen` 里的均量表头文案改为写 `dataset.label`，由 `renderSortHeaders()` 统一渲染，
  否则动态改 `textContent` 会把排序箭头冲掉
- 排序状态跨「重新选股」保持（用户先排序再调筛选，不该被打回默认）
- 新增「恢复默认」小按钮，仅在非默认排序时出现

**踩坑：排序箭头占宽导致 9px 横向溢出。**
`#screenTable th/td` 内边距从 6px 收到 5px，13 列共省 26px，逐列排序实测溢出均为 0。
**教训：这个表已贴到 970px 容器上限，任何给表头加内容（图标、箭头、角标）
都要重新量一次 `scrollWidth - clientWidth`，别假设还剩空间。**

**agent-browser eval 的坑**：超长 / 嵌套引号的单行 `eval` 会报
`SyntaxError: Invalid or unexpected token` 或 `Unexpected token ':'`。
绕法：① 拆成多个短 eval，用 `window.__x` 跨调用传值；
② 属性选择器用 `[data-sort=vol_ratio]` 不写引号，少一层转义；
③ 用 `function(){}.call` 或 `(function(){ ... })()` 而不是箭头函数混排。

## 21:00 打包成 Windows exe（PyInstaller）

**需求**：「帮忙把本软件打包成exe」。产出 `dist/stock_picker.exe` 单文件 65.2MB，
构建脚本在 `packaging/`（entry.py / build.py / make_icon.py / 两个测试脚本 + kill_port.py）。

### 核心是「目录分离」，不改这个必然丢数据

`config.py` 原来 `ROOT = Path(__file__).parent`，`DATA_DIR = ROOT/"data"`。
onefile 打包后 `__file__` 落在 `sys._MEIPASS`（**退出即删的临时目录**），
于是「打开 exe → 加自选 → 关窗口」数据就没了。改法：

- `RESOURCE_DIR = Path(__file__).parent` —— 代码 + static/，只读
- `APP_DIR = Path(sys.executable).parent`（冻结时）—— config.json + data/，可写
- 环境变量 `STOCK_PICKER_HOME` 可覆盖，用它就能复用源码模式那份 data/ 和 config.json
- 源码模式两者相等 → 零行为变化

因为所有可写路径都从 `config.py` 的 `DATA_DIR` / `CACHE_DIR` / `DEFAULT_CONFIG_FILE`
派生（`store.py` 的 backups 也是从 `db_path.parent` 推的），所以**只改这一个文件就够了**。
`app.py` 只需把 `STATIC_DIR` 从 `ROOT/"static"` 改成 `RESOURCE_DIR/"static"`。

### PyInstaller 必须显式声明的东西（漏了就是运行时 ImportError）

- `uvicorn.loops.*` / `uvicorn.protocols.*` / `uvicorn.lifespan.*`：uvicorn 用**字符串查字典**选实现类
- `pyarrow` / `pyarrow.parquet`：pandas 的 parquet 引擎是运行时 `import_optional_dependency`
- `pytdx.reader.*`、`pytdx.parser.*`：`shares.py` 在**函数内** import
- `--add-data stock_picker/static;stock_picker/static`：静态资源不是 .py
- `multiprocessing.freeze_support()`：没有它冻结后子进程会反复重开 exe

排除项原则：**只剔任何代码路径都不会 import 的**（matplotlib/scipy/tkinter/pandas.tests…）。
`pandas._testing` 一度想剔，撤了 —— 宁可大 20MB 也不要运行时报错。

- 冷启动 15s（解包 + 建索引）；热启动 **3.1s**

- 强杀验证：`taskkill /F` 后 WAL 残留 309KB 未 checkpoint，重启后计划 3 条/追踪 2 条逐字段一致

**1. `/api/jobs/{id}` 是嵌套结构！** 返回 `{"ok":true,"job":{"status":"done",...}}`，

## 22:00 修复：分布卡点选一个行业后，其余行业全部消失

**现象**（用户报告）：在「二级行业分布」卡里点选一个行业，之后其他行业标签全部消失，
既没法切到别的行业，也看不出该行业在整体中的占比。概念分布卡同理。

**根因**：`service.py` 里 `industry_summary` / `concept_summary` 是在**行业、概念过滤之后**
才统计的（过滤在第 409–424 行，统计在第 444 行）。一旦带着 `industries` 参数重选，
`hit` 已经只剩那一个行业，分布自然只剩 1 项，`…另有 N 个行业` 随之消失。

**修法**：

1. 新增统计基数 `summary_codes = hit["code"].drop_duplicates().tolist()` —— 取
   「**除行业/概念筛选本身以外**的全部条件命中集」，两张分布卡都改用它统计，
   并通过新字段 `summary_base` 把基数返回给前端。
2. 把**流通市值过滤前移**到行业过滤之前，让基数口径完整（已含市值条件）。
   纯顺序调整，逐项回归确认语义未变。
3. 前端 `renderIndustrySummary` / `renderConceptSummary`：
   - meta 改用 `summary_base`，并显示「已筛「X」→ N 只」；

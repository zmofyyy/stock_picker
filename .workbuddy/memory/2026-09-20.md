### 实测得到的两个关键结论（已写入 README 第五节）
1. **pytdx 覆盖范围**：`SECURITY_TYPE` 表只含沪深主板/创业板等。
   `688xxx.SH`（科创板）抛 `Unknown security type`、`8xxxxx.BJ`（北交所）抛
   `Unknown security exchange`，必须回退内置解析器。回退是**按文件粒度**的。
2. **成交量量纲（日线与分钟线规则不同！）**：
   - 日线 `.day`：文件单位「股」；pytdx 遵循 zipline 约定做了 ÷100 返回「手」
     → 归一化需 ×100 还原为「股」。
   - 分钟线 `.lc1/.lc5`：pytdx **不做**换算，原样返回「股」→ 不需缩放。
     `_from_pytdx(raw, scale_volume=...)` 用参数区分，日线 True / 分钟线 False。
   归一化后 `volume` 恒为「股」、`amount` 恒为「元」。

### pytdx 方法名差异（踩坑）
- `TdxDailyBarReader` 有 `get_df_by_file`；`TdxMinBarReader` **没有**，
  只有 `get_df(fname)` / `parse_data_by_file(fname)`。
  读取层改为按 `_PYTDX_GETTER_METHODS` 候选顺序探测，否则分钟线会**静默**永远走回退。
- 分钟线文件里 OHLC 是「价格 ×100 的 int32」而非 float32，布局 `<HHIIIIfII`。
  内置备用解析器与演示数据生成器原来都写成了 `<HHfffffII`，导致价格错乱，已统一。

### 修复的真实缺陷
- pytdx 返回的索引名是 `date` 而非 `datetime`，导致**所有**文件都被判为解析失败而回退
- 上述量纲不一致
- 状态机：`清仓 → 减仓 → 持仓` 反复抖动 → 引入 CLOSED_STATES 短路，离场后只认新买入信号
- 风险提醒「跌破关键均线」连续多日重复 → 增加同类提醒去重
- `watchlist.add_many` 条目自带 `overwrite` 与形参冲突、条目默认分组覆盖批量分组
- storage：日期/日期时间字段未做类型归一导致写入报错
- 回测 `_execute` 的 fixed 仓位规则未生效
- 状态机 `can_transition` 允许 `暂停 → 任意` 但需求要求暂停为终态 → 改为「暂停时记住原状态、恢复时还原」
- 首次进入「持仓」时提示语误用「继续持有」→ 区分建仓与继续持有

## 追加需求：选股策略「小于 150 亿流通盘 + 放量 20 日均量 2 倍」

用户原话：「选股策略加入 小于150亿流动股本的股票放量20日均量线两倍」。
「150 亿流动股本」有两种合理理解（流通**市值** 150 亿元 / 流通**股本** 150 亿股），
因此**两种口径都实现**，用参数 `cap_metric` 切换，默认取「流通市值」。

### 新增文件
- `backend/app/data/basics.py`：`StockBasicResolver` 读 `<cache_dir>/stock_basic.csv`
  （列 `code,name,float_shares,total_shares,industry`）；`parse_shares` 支持
  `65.7亿 / 3500万 / 1,234,000 / 整数`；`attach_float_shares(df, code, resolver)` 负责注入。
- `backend/app/strategies/volume_surge.py`：`VolumeSurgeStrategy`（name=`volume_surge`，
  中文名「小盘放量（20日均量2倍）」）。
- `tests/test_volume_surge.py`（34 项）、`tests/test_cli_overrides.py`（3 项）。

### 核心设计（重要）
1. **通达信 `.day` 不含股本**，所以流通盘必须外部补数据；缺数据时默认**剔除**该股，
   并给出告警（策略参数 `allow_missing_basics=true` 才放行）——绝不把「未知」当「符合」。
2. `BaseStrategy` 新增类属性 `requires_basics: bool`；`describe()` 一并返回。
   选股器 / 回测引擎 / 追踪器只在 `strategy.requires_basics` 为真时，
   在调用策略前给 K 线注入 `float_shares` 列（三处口径一致，杜绝「回测一套、追踪另一套」）。
3. 流通市值 = 流通股本 × 当日**收盘价**，实时算、不落库，避免静态市值字段过期。
4. 均量默认 `exclude_current_volume=True`（用前 20 日均量），仍只依赖当日及之前数据，无未来函数。
5. 新增 CLI 子命令 `basics status|template|import|list`；API `GET /api/data/basics`、
   `POST /api/data/basics/template`、`POST /api/data/basics`；前端「数据管理」页新增卡片。

### 修复的真实缺陷（顺手发现）
- **`parse_cli_overrides` 返回扁平键**：`--set data.tdx_dir=./demo_tdx` 被写入顶级键
  `"data.tdx_dir"`，`Config.update` 的 deep_merge 根本改不到 `data.tdx_dir`，
  即 CLI 的 `--set` 点号路径**一直静默失效**。已改为逐层下钻构造嵌套字典，并加回归测试。
- `config.demo.yaml` 的 `tdx_dir` 原为 `D:\new_tdx`，与 README 描述（应指向 `./demo_tdx`）
  不一致且会让演示扫到真实全市场（9626 只）而极慢 → 改为 `./demo_tdx`。

### 复用方法：如何判定"某端口上的服务属于哪个项目"

1. `Get-CimInstance Win32_Process -Filter "ProcessId=<pid>"` 取 `CommandLine`（wmic 已不可用）；
   输出重定向到文件再用 Read 读（本机 PowerShell 工具不回显 stdout）。
2. `netstat -ano` 输出是 **GBK**，Python 读取需 `decode('gbk', errors='replace')`，否则 UnicodeDecodeError。
3. 命中一个**特征接口**，对比候选项目的路由实现差异（本项目统一 `{"ok":true,...}` 信封）。
4. 仅凭端口号相同不能认定归属。

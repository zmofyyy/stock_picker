### 关键技术发现（本轮新探明）

1. **`blocknew.cfg` 不是定长记录**（2520 字节）：
   每字段以 `\x00` 结尾且**跨记录边界连续** → 必须按「连续非 0 段」切字段流，再**两两配对**
   （前一个 = GBK 中文显示名，后一个 = ASCII 文件名）。
   实测 **42 段 → 21 组配对，21/21 命中磁盘**，零错配、零坏字节。
   **踩过的坑**：最初按「50 字节 = 25 名 + 25 文件名」切 → `集合竞价大量` 被切成 `集合` + 半截跑到下一条记录尾部。
2. **`.blk` 字节数 = 行数 × 9**（21 个非空文件逐项精确成立），不是 ×7。
   布局是「`\r\n` + 7 位代码」逐行重复、**无尾换行** —— 首个 CRLF 与「无尾换行」正好抵消。
   空板块（`2-12.blk` / `zxg.blk`）是 **0 字节**。
   **测试里我先写 ×7、再 ×9+2，都失败**，实测逐项验证后才定下 ×9。
3. **`.blk` 首位是市场码**：`0`→深(sz)、`1`→沪(sh)、`2`→北(bj)，后 6 位是股票代码。
   文件里除数字与 CRLF **零杂字节** → 「提取全部数字按 7 位切」与「按行解析」完全等价，
   且对行尾换行风格不敏感（所以 `parse_blk` 用前者）。
4. **磁盘 23 个 `.blk`，cfg 只收 21 个**：多出的 `tjg.blk`(140 只) / `zxg.blk`(0 只) 是通达信内部文件，
   不入清单一律进 `meta.verify.orphan_files`。
5. 23 个文件共 **2304 行 → 去重 1603 码**，`is_a_share()` 过滤后**仍是 1603（零剔除）**。
   按首位（`0`=1094 / `1`=1206 / `2`=4）与按后缀（sz 1094 / sh 1206 / bj 4）两种口径
   经 `MARKET_PREFIX` 折算后**逐项相等** → 映射正确性得到证明。
   （**测试坑**：直接拿 raw 的 `{'0':…}` 与后缀 `{'sz':…}` 比永远不等，必须先折算。）
6. 类别分布：主板 1376 / 创业板 143 / 科创板 80 / 北交所 4；21 板块成员合计 1514 只。
7. `blocknew.clr`（颜色）、`zxgmore.dat`（二进制属性）本工具**不解析**。

## 追加：修「自选板块 dropdown 显示有问题」

用户反馈原话：「自选板块 dropdown 显示有问题」。

### 根因

`loadWatchBlocks()` 里的 tag 生成逻辑：

```js
const label = b.name && b.name !== b.key ? `${b.name}（${b.file}）` : b.file;
return `<option ...>${esc(label)} · ${b.n}</option>`;
```

两个毛病：

1. **`.blk` 后缀是噪音** —— 显示 `均线纠缠_初选（JXJC_CX.blk） · 193`，文件名对用户没意义。
2. **两套不一致的格式** —— 21 个板块里有 **9 个 `name == key`**（用户没改过名，
   通达信把文件名当显示名：`60-11-14` / `GL-12-03` / `GL20-12-04` / `MACD_1-09` / `MACD_1-23` / `2-12` …），
   它们走 `b.file` 分支 → 渲染成 `60-11-14.blk · 231`；有名的那 12 个走另一个分支。
   同一列里两种排版。
3. **宽度被撑破** —— 长标签要 238px，原生 `<select>` 会把选项文字截断。

另外「条件栏」`renderWbConditions` 也拼了 `（JXJC_CX.blk）`，同样的噪音。

### 修法（3 个文件，纯前端）

| 文件 | 改动 |
|---|---|
| `static/app.js` | `loadWatchBlocks()`：标签改成 `显示名 · 成员数`（`b.name \|\| b.key`），空板块显示 `空` 并置灰；`renderWbConditions()`：**只有 `key !== name` 时**才补 `（key）`，且去掉 `.blk` |
| `static/style.css` | `#wbSelect` 宽度 `min 190 / max 320` → **`min 150 / max 220`** |
| `static/index.html` | 下拉 `title` 补一句说明「· N」是成员数、空板块不可选 |

结果：`均线纠缠_初选 · 193` / `60-11-14 · 231` / `2-12 · 空`（置灰），
宽度 238 → **150px**，`scrollW == clientW == 148`（不再截断）。

### 验证（headless Chrome + CDP，指向正在跑的 8778）

- 下拉 **21 项**、选中项 `均线纠缠_初选 · 193`、宽度 150px、无横向溢出
- 条件栏：`自选板块 均线纠缠_初选（JXJC_CX） · 成分 193 只`（改名板块仍带文件名，便于对磁盘）

### ⚠️ CDP 踩坑（重要，下次直接用修正版）

探针一开始全部失败，症状很有误导性：`tabs=0`、`switchTab is not defined`、
`sel=true 但 n=0`。**全都是探针的错，不是页面 bug**：

1. **`list[0]` 不一定是页面 target** —— 本机 headless Chrome 会同时挂

## 追加：自选板块 dropdown 真正的问题 —— Windows 上 `<option>` 白底白字

用户澄清原话：「只能看到 hover 的 item，其他显示白底」。

**上一轮我修的是文案（`.blk` 噪音），没修到这个** —— 这是两个独立问题，用户说的其实是后者。

### 根因

`:root { color-scheme: dark }` 在 **macOS** 上足够让原生下拉弹层变暗；
但 **Windows 上的 Chrome/Edge 常把弹层底仍涂成系统默认的白色**，
而 `<option>` 的文字**继承了作者的 `color: var(--text)`**（`#f5f5f7`，接近纯白）
→ **白底 + 白字 = 看不见**，只有鼠标悬停时系统用蓝色高亮才显出来。

全项目**从没有过 `option` 的配色规则**（只有一条 `#wbSelect option:disabled`），
所以这个 bug 其实**影响所有 `<select>`**（全部行业 / 任一·全部 / 状态 / 自选板块），
只是自选板块那个刚用过、最显眼才被报出来。

### 修法（`static/style.css`，1 处插入 + 1 处清理）

在 `[hidden]` 重置之后插入**全局**规则：

```css
select option { background-color: var(--surface); color: var(--text); }
select option:disabled { color: var(--muted); }
```

同时删掉原来 `#wbSelect option:disabled` 那条（被全局规则覆盖了）。

- `option` 的 `background-color` **只在弹层里生效**，不影响 `<select>` 本体
  （本体的深底由 `.filters select` 的 `background: var(--deep)` 负责）。
- 新增任何 `<select>` 都不用再单独处理。

### 验证

CDP 读计算样式（`#fIndustry`，129 个 option）：

```
select  : color rgb(245,245,247) / bg rgb(28,28,30)  / colorScheme dark
option0 : 全部行业  → color rgb(245,245,247) / bg rgb(58,58,60) / colorScheme dark
option1 : 煤炭开采  → color rgb(245,245,247) / bg rgb(58,58,60) / colorScheme dark
```

深底 `rgb(58,58,60)` = `--surface`，浅字 `rgb(245,245,247)` = `--text` —— 不再是白底白字。
CSS 括号/注释配平自检通过（283/283、63/63）。

### 教训

- **「显示有问题」要追问到底**：同一个功能下「文案冗余」和「配色不可见」是两个 bug，
  上一轮我按自己的判断只修了前者，用户不得不再说一遍。
  以后遇到这类模糊反馈，先把可能的几类（文案/配色/宽度/溢出）都过一遍，或直接问。
- **主题适配不能只靠 `color-scheme`**：`color-scheme` 在跨平台的原生控件上不可靠，
  **凡是交给 OS 绘制的部分（下拉弹层、日期选择器、滚动条）都要显式配色**。
  这个项目的 `.filters input[type=checkbox]` 已经用 `appearance:none` 自绘了，
  下拉是最后一块漏网的。

## 十、自选板块**动态扫描**（用户：「没有动态扫描自定义板块里面的板块」）

### 诉求

在通达信里新建 / 改名 / 删掉自选板块后，页面**不更新**，非得重启服务。

### 根因是**两层**都写死了

| 层 | 原实现 | 问题 |
|---|---|---|
| 后端 | `watch_block_catalog()` 直接 `catalog()` 返回内存索引 | 只在启动时 `load()` 过一次，之后从不重算指纹 → 永远旧快照 |
| 前端 | `loadWatchBlocks()` 被 `state.wbLoaded` 锁死 | 只在首次切 tab 时跑一次，之后切回来直接 return |

### 修法

**后端** `watchblocks.py` 新增 `refresh()`（`load(force=False)` 的薄封装，每次重算 `_signature()`）；
`service.watch_block_catalog(refresh=True)` 默认先 refresh，**异常吞掉退回现有索引**（清单接口不能整个挂）。
`_signature()` 覆盖 `blocknew.cfg` + **目录下每个 `.blk`** 的 size/mtime，实测 **0.34ms（24 个文件）**，
放每次请求里完全安全。

**前端** 三处：
1. `switchTab('watchblock')` **每次切过来都重扫**（`loadWatchBlocks({keep:!first, notify:false})`）
2. 新增「重新扫描板块」按钮（`#btnWbRescan`），`{keep:true, notify:true}` —— 保留当前选中项 +
   **弹 toast 告诉用户这趟有没有变化**（没变化也反馈，否则用户以为按钮失效反复点）
3. `init()` 末尾**后台预取**一次（`silent:true`），首次点过去时下拉已就绪

### 语义澄清（回归测试逼出来的）

- **`blocknew.cfg` 是清单的权威来源**：只放 `.blk` 不写 cfg → 板块**不入清单**。这是对的
  （通达信增删板块时会同步写两处），已用测试第九节钉住。
- **指纹必须覆盖全部 `.blk`，不能只盯 cfg**：用户「往已有板块里加减股票」时 **cfg 一个字节不变**，
  只有那个 `.blk` 变了。这条正是本节最容易漏的。

## 十一、⚠️ CDP 探针的「首次进入为空」是**假警报**

上一轮遗留的疑点：探针显示首次进 watchblock tab 时 `#wbSelect` 为 0 个 option。

### 真相：两个探针侧的错，**应用侧没问题**

1. **`state` 不是全局的**（模块作用域）→ `(window.state && state.wbLoaded)` **恒为 `null`**，
   探针由此误判「没加载」。**要读状态就用 `typeof xxx` 或干脆看 DOM。**
2. **`list[0]` 挑错 target** → `background_page` / `browser_ui` / `service_worker` 排在最前，
   必须 `find(t => t.type === 'page' && t.url.includes(port))`；若页面还没导航过去，
   退化为取第一个 `type==='page'` 再自己 `Page.navigate`。

### 复现验证（冷启动对照）

改写探针：**等 `init()` 就绪 vs 冷启动 60ms 就点**，两种都正常：

```
EARLY click(60ms):  afterActive=true  → after: n=11 rows=189
LATE  click(init后):                   n=11 rows=189
```

且下拉配色也一起验了：`option` bg `rgb(58,58,60)` / color `rgb(245,245,247)`（白底 bug 确修）。

**结论**：之前那次 `n=0` 是探针在 `Page.navigate` 还没生效、或挑错 target 时 evaluate 出来的。
**应用侧 `switchTab` / `loadWatchBlocks` 逻辑正确。** 顺手加了两处稳健性加固
（`first` 改看 `state.wbPanel` 是否存在；`init()` 末尾后台预取），但不是修 bug。

### 教训

- **探针读不到 ≠ 应用坏了**。先自证探针（`typeof` 两个函数、打印 `document.querySelectorAll('.tab').length`），
  再下结论。**模块作用域变量不要用 `window.xxx` 去读**。

3. 数据流水线

整条链是「一次读盘、常驻内存、按日切片」的形态：本地文件只在启动时读一次，之后的选股/连板/交集都在这份内存长表上做向量化切片。

4. 三条核心算法

4.1 放量选股 —— 快在「不在 1600 万行上做逐行判断」

  • 均量口径：ma_volume 取前 M 日（不含当日）成交量均值 → 不引入未来函数。
  • 去重：同一只股票在回看窗口内多次放量，只保留最近一次信号。
  • 过滤下沉到类别层：代码前缀、板块、行业、概念这些「每股一份」的判断， 先对 5 608 个 category 算一次掩码，再 cat_ok[cat_codes] 展开成行级布尔。 逐行 .map(dict) 会又慢又费内存。
  • 均量与根数按需算：_attach_volume_stats() 只对命中行求前 window 根之和（约 5 600×20 = 11 万元素）， float64 逐值精确；bar_total 在类别上做一次 searchsorted，必须按锚点日取值， 否则回看 2022 年时 2022-05 才上市的票会被误判成「K 线充足」。

4.2 涨跌停与连板 —— 精度全部落在「分」上

  • 基准价 = 前一根 K 线收盘。文件第 8 个 uint32 名义上是「上日收盘」，但实测自 2015-12-16 起全市场失效 （多为占位值 65536 或 0），所以既不落缓存列，也不使用。
  • 涨停价 (prev_c × f + 50) // 100，用整数分算 —— 浮点会在 0.01 元边界上抖动。 f：主板 110 / 创业板·科创板 120 / 北交所 130 / ST 105。
  • 上市首日剔除；跌停额外要求「最低价 ≥ 跌停价」，用于排除除权造成的假跌停。
  • 封板形态：一字板（最低价 = 涨停价）/ T 字板（开 ≥ 涨停价但盘中打开）/ 换手板 —— 判断「明天还能不能继续」最直接的一眼信息。
  • 连板计数全向量化：(n_cat, window) 右对齐矩阵展平后 streak_all = np.where(boundary, 0, gp − accumulate(...))， 实测 0.05~0.16 s（含 2015/2018/2022 等历史日期），没有逐股循环。
本机数据里「ST 股 5% 带宽」并不成立。2026-09-23 实测：144 只名称含 ST 的主板股中 141~142 只（≈97.9%） 出现过「日内最高价 > 前收 × 1.05」，high/前收 的 p99.9 ≈ 1.10。 也就是说这批行情里主板 ST 的带宽也是 10%。因此 st_limit 默认关闭； 打开会把 2026-06-01 从 120 只变成 168 只。
教训：名称里的「ST」前缀 ≠ 5% 带宽 —— 判涨跌幅限制要看行情本身，不能只信名称。

4.3 板块交集 —— 一个纯集合问题

限定在「锚点日有行情 + 通过轻量过滤」的候选集内：A = 选中二级行业（多选为并集）、 B = 选中概念（可任一 / 全部），结果 = A ∩ B。

  • 行业侧只给并集：一只标的的二级行业是单值，选两个行业求交恒为空 —— 给「全部命中」反而误导。概念是列表，故 any / all 都有意义。
  • 空交集给「下一步往哪调」：把「A 里最常出现的概念」「B 里最常出现的二级行业」两组标签回给前端， 点一下就并入对应一侧。空结果本身没法自查，这两组数字就是自查入口。
  • 明确报错而不是静默空结果：未知行业/概念名、两侧都不选、空板块、空交易所、越界日期， 全部 ok=false + 原因，且走 HTTP 200 而非 500。
  • 口径透明：warnings 里会说明概念归属缺失只数，以及「回溯历史日期时，板块成分仍是本地文件的当前成份」—— 是「用今天的板块看历史行情」，不是历史快照。

6. 工程红线（改代码前先过一眼）

红线为什么
重建缓存必须拿 _refresh_lock，并在锁内重判 freshness 否则「启动预加载」与手点「刷新数据」会同时写同一个 bars.parquet.tmp
volume 必须 uint32 float32 在 41.7 亿股处 ULP = 256 股，前端「手」会偏 1~2 手；源本身就是 u4，无损
bar_total 按锚点日取值，不是整段历史长度 否则回看历史日期时，上市晚的票会被误判成「K 线充足」
分布卡基数 summary_base 在过滤之前取快照 放在之后会导致「点一个行业后，其余行业标签全消失」
as_multi() 必须挡住裸字符串 [b for b in "主板"] → ['主','板'] → 静默匹配不到、返回空结果不报错
#klineChart 必须是 .drawer-body 的直接子元素 曾因多一个 </div> 被解析到 .drawer 下，控制台无报错、页面照常打开，但图表被压扁
前端改动必须走资源指纹（?v= + 响应头） 否则旧标签页继续跑旧 app.js，表现是「改了前端没生效」，极易误判成后端问题
测试脚本只允许删自己创建的数据 persist_test.py 曾因遍历接口全部条目 DELETE，在有用户数据的库上跑一次就全删光
测试里不写死「A 股总数 / 命中数」 数据一更新（新股/退市）就变成过期假失败，只写不变量与交叉核对

8. 已知限制（README 第 8 节有完整版）

  • 数据不复权：长期回看时除权股价格与均量会跳变；连板判定在除权日可能漏判涨停（唯一无法靠数据修掉的一点）。
  • 创业/科创板上市前 5 个交易日、北交所首日、停牌复牌当天无涨跌幅限制，本口径只剔除上市首日。
  • 流通股本是「最近一次股本变化」的值，不是逐日历史股本 → 用历史日期回看时市值用的是当前股本。
  • 板块归属（行业 / 概念）都是当前值，不是历史快照；167 只 A 股在本地文件里没有任何概念归属。
  • 概念数多 ≠ 题材强（平均每股 8.56 个、最多 49 个），工具只做归属展示与筛选，不做题材强度打分。
  • 连板梯队的基准交叉核对依赖兄弟项目 stock_watch 的 universe.parquet； 该文件随 F: 盘一起消失，要重跑这条校验得先找回兄弟项目。
  • 工具只做筛选与记录，不构成任何投资建议。
